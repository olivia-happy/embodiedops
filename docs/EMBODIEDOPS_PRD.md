# EmbodiedOps 产品需求文档（PRD）

版本：v1.0（2026-08-30）
状态：MVP 已实现，本文档补齐产品定义层
关系：EmbodiedOps 是 SignalForge 工作台中的具身智能诊断模块。`SIGNALFORGE_PRD.md`（原 PRD.md）描述的是 SignalForge 舆情决策工作台本体，本文档只覆盖 EmbodiedOps。

## 1. 一句话定位

面向具身智能团队的**本地、只读**机器人任务失败诊断工作台：把一次失败的 episode 从"记成 fail"变成"可复核的诊断单元 + 可执行的仿真实验草案"。

## 2. 背景与问题

机械臂 pick-and-place 任务失败后，现有做法只记录成功/失败两个结果。这无法回答四个关键问题：

1. 失败发生在哪个阶段（approach / align / grasp / transfer / place）？
2. 支持该判断的事件证据是什么？
3. 证据有没有反例？
4. 下一步应该验证什么？

后果：每次失败都依赖工程师从日志手工猜原因——定位慢、口径不一致、无法判断一次参数调整到底在改善什么。

## 3. 目标用户与场景

| 用户 | 场景 | 得到什么 |
| --- | --- | --- |
| 机器人产品经理 / 技术 PM | 失败复盘会、周度失败分布 review | 失败分布、带证据的归因草案、实验优先级依据 |
| 算法工程师 | 迭代策略前的假设验证 | 受控 Agent 给出的候选机制 + 反例校验结果 |
| 测试团队 | 回归验证 | 版本化 episode 契约、可重放的确定性指标 |

## 4. 产品目标与指标

当前阶段（MVP）：交付完整可复现的闭环演示 + 评测门禁，不声称真实业务效果。

接入真实数据后的目标指标（分层定义，见第 8 节）：

- 业务层：人工接受率 ↑、单次失败诊断耗时 ↓、任务成功率 uplift、碰撞/超时护栏不劣化
- 系统层：未知事件拒答率、Trace 与数据版本一致性
- 模型层：阶段判断准确率、证据精确率/覆盖率、该拒答时的拒答正确率

## 5. 核心流程

```text
版本化 Episode JSONL 导入（SHA-256 manifest 校验）
  → 结构校验（缺字段/坏版本直接失败关闭）
  → 确定性规则：五阶段切分 + 成功率/碰撞率/超时率/失败分布
  → 受控诊断 Agent：仅见 allowlist 摘要与事件 ID，产出候选机制
  → 验证器：逐条校验事件 ID、时间窗、数值主张与反例
  → 输出：带 Trace 的诊断草案（证据不足 → needs_evidence；越界 → 拒绝）
       + 实验草案（强制 simulation_only 标记）
  → 人工审核 → 才允许进入仿真或真实机器人流程
```

## 7. 关键产品决策：AI 边界

这是本产品与"聊天机器人界面"的本质区别，也是面试叙述的核心：

| 环节 | 谁负责 | 为什么 |
| --- | --- | --- |
| 数值与指标 | 确定性规则 | 同版本数据可重放，模型不许生成数值 |
| 候选机制归纳 | 受控 Agent | 擅长把受限证据整合成人类可读假设 |
| 结论是否成立 | 验证器 | 事件 ID / 时间窗 / 数值 / 反例逐条校验 |
| 下一步动作 | 人工审核 | 系统无任何控制接口，实验仅 simulation_only |

fail-closed 原则：未知事件、越界时间、伪造数值、反例缺失 → 拒答或返回 `needs_evidence`，绝不编造结论。

## 8. 评测方案（三层拆开）

离线评测由 `eval/run_embodied_eval.py` 从 `eval/embodied_gold_cases.jsonl` 可复现生成（数据集 `embodied-demo-v1`，5 例合成 fixture，`live_model=false`，0 次实时模型调用）：

| 指标 | 数值 | 说明 |
| --- | --- | --- |
| phase accuracy | 5/5 = 1.000 | |
| event evidence precision / coverage | 3/4 = 0.750 | fixture 刻意注入 1 个未知事件引用，验证 fail-closed；被拒绝后不得成为系统证据，**不是模型能力结论** |
| refusal correctness | 4/5 = 0.800 | |
| decision status accuracy | 5/5 = 1.000 | |
| validated event evidence | 3/3 = 1.000 | 验证后证据全部有效；`persisted_unknown_event_ids = 0` |

验收标准：每个持久化 AI 结论包含有效证据 ID；证据不足拒答；数值不由模型生成；空数据、失败、过期快照均有界面提示。

## 9. 数据边界

- 当前：合成桌面抓取 fixture（`synthetic_tabletop_fixture`），用于回归测试与页面回放。
- 未使用 Unitree、优必选、傅利叶或任何公司的真实生产数据；页面不发送控制命令，不接入真实机器人执行链路。
- 扩展到真实数据的前置条件：数据许可、脱敏、固件/任务元数据、保留与删除规则、按任务分层的 holdout、人工根因标注、shadow mode 逐层验证。缺任一项，系统拒绝做 sim-to-real 或 ROI 主张。

## 10. 非目标

- 不做机器人控制，不接生产执行链路
- 无账户体系、多租户、远程数据外传
- 不自动执行实验，不把合成数据包装成生产 ROI
