# SignalForge AI 决策台重绘设计

## 目标

将 SignalForge 从基础后台样式重绘为“中式现代 × AI 决策实验室”。产品应在首屏先给出值得推进的行动，再让用户逐层验证其证据、评分、风险与不确定性。页面必须直接消费现有本地 API，继续可在 `http://localhost:3000` 运行，不使用付费字体、图标、素材、API 或部署服务。

## 产品原则

- 结论优先：用户首先看到一个最需要推进的行动，而不是分散的指标卡。
- 证据可达：每一个行动结论可展开至数据版本、样本量、评分拆解、证据数量和原文。
- 不确定性可见：没有洞察或证据不足时，明确展示缺少的条件，绝不伪造 AI 结论。
- 有张力但可读：视觉大胆而节制，数据与操作不依赖纯颜色区分。

## 视觉语言

页面采用“朱印·决策台”主题。宣纸暖白是阅读底色，墨黑承担结构和粗线框，朱砂红表示需要关注的负向与紧急状态，松石青表示可信、可执行和健康状态，少量鎏金用于分数与重点标记。颜色使用 CSS 变量管理，字体只使用系统和现有中文字体回退。

中式感来自印章式标签、粗线分区、折页式层级与纵向阅读节奏，不使用传统纹样或仿古装饰。AI 感来自数据脉冲、层层展开的推理链、置信状态和适度的动效；动效在 `prefers-reduced-motion` 下停止或简化。

## 信息架构与交互

### 决策台（首页）

1. **状态带**：展示数据快照、数据健康状态、样本数与最后导入时间。细微脉冲只表示页面和数据处于可用状态，不暗示实时更新。
2. **主决策卡**：选取 API 返回的首个机会作为“优先行动”。卡片展示主题、优先级、负向率、样本量和证据数，并用一句基于真实字段的行动建议解释为什么应优先处理。
3. **决策折页**：点击主卡或“展开依据”后在原位置展开；内容包括各评分贡献、原始证据入口、数据版本，以及需要人工验证的未知项。不能因为 API 缺少字段而编造内容。
4. **机会队列**：其余机会以紧凑可展开卡展示，使用户能比较优先级而不会淹没主结论。
5. **风险联动区**：显示风险评分最高的少数风险；进入完整风险页后可追溯来源与缓解动作。

### 用户洞察

将主题分布重构为“信号谱”，每个主题同时编码样本量、负向比例、严重程度与是否达到评分条件。点击主题筛选页面内容。

当 `insights` 为空时，显示“尚未形成可验证洞察”的明确状态，并使用真实主题指标引导用户先审阅信号和证据，而非展示虚构的 AI 文案。已有洞察时，每条洞察显示置信度、主张、建议动作、未知项和证据抽屉入口。

### 决策实验室

保留现有真实表单和提交 API。创建后的结果强调问题、假设、主指标、护栏指标、评分拆解、绑定数据版本与 Trace；所有操作均保留失败与加载状态。

### 风险雷达

以纵向“风险脉络”呈现事件。每个事件显示发布日期、类型、风险分、证据质量、来源链接、责任人、缓解动作与状态。按高分优先而非伪造时间关联；详情可折叠以控制信息密度。

## 组件边界

- `Navigation`：响应式导航、品牌与数据快照标记，不保存页面业务状态。
- `DecisionHero` / `DecisionFold`：只接收机会和数据版本字段，负责首屏行动与可展开依据。
- `SignalSpectrum`：只接收洞察指标，负责主题的可访问可视化与筛选回调。
- `EvidenceDrawer` / `TraceDrawer`：继续负责异步加载和关闭交互；补足加载、空和失败状态。
- `RiskTimeline`：只接收风险 API 返回值，负责排序、展示和详情展开。

可复用的状态标签、评分标记、骨架屏和区块标题应是小组件或共享样式，避免页面中复制样式逻辑。

## 数据流与真实性

前端继续从现有 `getOverview`、`getInsights`、`getEvidence`、`getRisks`、`createDecision` 和 `getTraces` 函数请求本地 API。重绘不会修改数据库、评分规则或数据导入。

UI 文案根据 API 可用字段形成：例如“服务体验：4 条样本、75.0% 负向、4 条证据”。若 `score`、`negative_rate` 或洞察为空，显示“不足以判断”或引导下一步，而不是推测原因。

## 错误处理、可访问性和响应式

- 各请求保留加载、失败、空数据和重试状态。
- 折页、抽屉、按钮和筛选器可通过键盘操作，有可见焦点；颜色之外还以文字和图标/形状传达状态。
- 桌面使用固定侧栏和多列信息区；900px 以下折叠为顶部导航和单列；不会因动画阻塞内容阅读。
- 所有新增动效采用短时 CSS transition，不依赖第三方包或网络资源。

## 验收标准

1. 首页能一眼识别首要行动及其优先级、负向率、样本量、证据数和数据版本。
2. 用户可以无需离开首页展开一个行动并查看评分依据和原始证据入口。
3. 洞察为空时页面仍展示真实信号与清晰的证据不足提示。
4. 既有创建决策、反馈、Trace、筛选与风险来源流程继续可用。
5. `npm run build`、前端测试、Docker 本地验证通过；`http://localhost:3000` 和窄屏均可正常打开。
6. 不新增任何付费服务、远程 API 或素材依赖。
