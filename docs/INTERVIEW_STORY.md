# EmbodiedOps 面试叙事

这份叙事用于解释产品判断、数据边界和工程取舍。所有表述以公开仓库当前事实为准：演示数据为合成数据，系统不控制机器人，未使用 Unitree 或其他公司的真实生产数据。

## 90 秒版本

我做的是 EmbodiedOps，一个面向具身智能团队的机器人任务失败诊断与策略迭代原型。它从一个很具体的问题出发：抓取失败不能只记成 fail；产品、算法和测试团队需要知道失败发生在哪个阶段、哪些事件支持判断、有没有反例，以及下一步要验证什么。

我先把机械臂 pick-and-place 拆为 approach、align、grasp、transfer、place 五个阶段，再把 episode、事件、结果和数据版本做成严格契约。确定性规则负责阶段切分和成功率、碰撞率、超时率等数值；Agent 只看摘要和允许事件，生成候选机制与实验草案。它不能发控制指令，未知事件、时间越界、伪造数值或缺少反例时会拒答。

目前公开演示是 30 条**合成**轨迹和离线回归，不声称真实机器人或 Unitree 数据效果。我想展示的是 AI 产品经理的完整闭环：数据契约、特征工程、受控 Agent、评测、人工审核与业务指标，而不是做一个会聊天的机器人界面。

## 5 分钟版本

### 1. 为什么选这个问题

具身智能团队的难点不只是训练模型，而是把大量失败回放变成能推动下一轮迭代的证据。若每次失败都依赖工程师从日志里手工猜原因，定位慢、口径不一致，且难以判断一个参数调整到底在改善什么。

### 2. 产品如何工作

一次 episode 进入系统后，先做不可变版本与结构校验；接着用确定性规则切分五个阶段，计算碰撞、超时、成功率和失败分布。然后受控 Agent 在白名单事件中提出“可能的机制”，验证器检查每个事件 ID、时间窗、数值与反例。最终输出的是带 Trace 的诊断草案和仿真实验建议，而不是对真实机器人执行操作。

### 3. 为什么这样使用 AI

AI 擅长把受限证据整合为工程师可读的假设，但不适合在缺失数据时编造数值，也不应直接下发动作。因此我把系统分为：规则计算事实、Agent 生成候选、验证器决定是否接纳、人审决定是否进入仿真或真实流程。这个边界是产品安全与可解释性的关键。

### 4. 如何评测和落地

我把模型质量、系统安全和业务效果拆开。模型层看阶段判断和事件证据；系统层看未知事件拒答、Trace 与版本一致性；业务层才看人工接受率、诊断耗时、成功率 uplift 和碰撞/超时护栏。现在的样例是**合成**离线回归，所以不能称为真实提升或生产 ROI；拿到经过许可的真实数据后，才会按数据卡、holdout、双审标注和 shadow mode 逐层验证。

### 5. 为什么适合机器人公司

对 Unitree 等具身智能公司，我不会声称这套原型使用了它们的数据。我会把它作为对数据闭环产品能力的展示：能够定义 episode 与标注规范、建立评测门禁、把 Agent 放在安全边界内，并用业务 KPI 组织从失败发现到策略验证的路线图。

## 深挖问答

### 你解决的业务问题是什么？

把“机器人任务失败”从单一结果变成可复核的诊断单元，减少定位时的来回沟通，并让实验优先级能被数据和风险护栏共同约束。

### 特征工程做了什么？

以阶段时间窗组织观测和事件，抽取夹爪状态、末端位姿、规划可达性、碰撞/遮挡与相对时间。阶段不是由大模型自由判断，而由规则稳定产出，保证同一版本可重放。

### Agent 是否是 autonomous agent？

不是。它是一个受限的诊断工作流：上下文有 allowlist，输出必须经过验证，失败时拒答，且没有任何控制接口。实验仅标记为 `simulation_only`，人审才有权决定下一步。

### 使用的是真实模型还是在线模型吗？

公开 demo 的离线快照标记为 `live_model=false`。本地 Ollama 是可选适配，不需要 API key，也不应把当前离线样例说成实时模型质量或线上 SLA。未来接入任意模型都要单独做版本、延迟、成本、安全和质量评测。

### 数据从哪里来，能否扩展到真实业务？

当前为合成 pick-and-place fixture，用于回归测试与页面回放。扩展到业务前必须有许可、脱敏、固件/任务元数据、保留/删除规则、holdout 和人工根因标注。没有这些输入，系统拒绝作 sim-to-real 或 ROI 主张。

### ROI 怎么算？

先记录真实基线：每类失败的排查工时、仿真轮数、任务成功率、碰撞/报废成本与人工接受率；再与受控实验后的 holdout 对比。仓库中的 before/after 只是合成案例，因此不形成 production uplift 或 ROI 的结论。

### 如果你入职后，前 90 天会做什么？

前 30 天：访谈测试、算法、现场运维，统一 episode 与失败 taxonomy，确认数据授权和安全红线。第 31–60 天：建设标注双审、离线 holdout、回放与诊断评测；先以 shadow mode 服务工程师。第 61–90 天：在仿真与小范围许可数据上验证诊断可用性、人工接受率和安全护栏，再决定是否扩大试点。

## 演示顺序

1. 打开 `/embodied`，先说明当前是只读、合成数据与不控制机器人；
2. 选择一条失败 episode，沿事件回放说明阶段和证据；
3. 展示证据/反例/未知项如何约束 Agent 的结论；
4. 展示 `simulation_only` 实验草案及停止条件；
5. 回到评测、数据卡和业务 KPI，说明下一步真实验证门禁。
